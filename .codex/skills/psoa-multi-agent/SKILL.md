# PSOA 多 Agent 架构

## 项目概述

PSOA 是一个基于三线程协作的多 Agent 系统，用于复杂推理任务的生成、审查和策略进化。

### 核心架构

- **G 线程（生成）**：接收任务描述和策略提示，生成候选输出
- **R 线程（审查）**：以极高标准审查，输出严格的 JSON 格式错误报告
- **L 线程（逻辑）**：负责逻辑推理和验证
- **I 线程（策略进化）**：使用 retained/modified/new 结构进行策略迭代

### 关键特性

1. **JSON 结构化输出**：所有线程必须输出标准 JSON，使用 extract_json 容错
2. **滑动窗口审查历史**：最多保留最近 N 轮审查记录，超过后压缩摘要
3. **R-L 对冲机制**：R 标致命时必须说明为何仍放行
4. **策略进化**：I 线程根据审查结果动态调整生成策略

## 配置说明

### Config 类关键参数

- RESULT_MODE: 输出模式（notify/log/file）
- QUESTION: 当前推理任务
- MAX_ROUNES: 最大迭代轮数
- TASK_TYPE: 任务类型（推理/创作/分析等）
- REVIEW_WINDOW: 滑动窗口大小（默认 3）
- REVIEW_SUMMARY_MAX: 审查摘要最大长度（默认 800）

### API 配置

- API_KEY: 从环境变量 AGNES_API_KEY 读取
- BASE_URL: API 端点地址
- MODEL: 使用的模型名称

## 审查标准

### R 线程致命标准

- 任何事实性错误 → 致命
- 逻辑矛盾/自相矛盾 → 致命
- 关键前提遗漏导致结论无法推出 → 致命

### 审查等级

- **致命**：必须修正才能继续
- **严重**：推理过程有瑕疵但不影响结论
- **轻微**：纯表述优化、措辞建议

## 开发指南

### 修改 System Prompt

1. 定位到 G_SYSTEM、R_SYSTEM、L_SYSTEM、I_SYSTEM 变量
2. 保持 JSON 格式约束
3. 确保审查标准明确无歧义

### 添加新线程

1. 定义新的 System Prompt 模板
2. 在异步函数中添加对应的协程
3. 更新结果合并逻辑

### 调试技巧

1. 查看 output/ 目录下的日志文件
2. 检查 JSON 解析是否成功
3. 验证滑动窗口是否正常工作
4. 监控 R-L 对冲标记是否正确

## 最佳实践

- 保持 System Prompt 简洁明确
- 使用模板化设计便于扩展
- 所有输出必须是有效 JSON
- 错误处理要健壮，避免单点故障
- 日志记录要完整，便于追溯

## 扩展方向

1. **更多线程类型**：可根据需要添加 C（创意）、T（测试）等线程
2. **动态权重**：根据任务类型调整各线程权重
3. **并行优化**：利用 asyncio 提高并发效率
4. **持久化**：将审查历史存入数据库而非内存
5. **可视化**：生成协作流程图和审查报告
